Recovery and history

Undo/Redo, session autosave, recovering unsaved work and memory limits.

Undo / Redo

  • Ctrl+Z - undo, Ctrl+Y - redo.
  • The history stores lossless compressed (GZip) state snapshots.
  • The limit is 50 entries and 64 MiB of compressed data in total per document, including Redo. Snapshots that are too large are evicted.
  • The limit does not include interface state, textures and temporary buffers.
  • A new action after an undo creates a history branch (Redo is reset).

History performance

The View > History performance window shows the size of the compressed history, the size of the source strings, the Capture / Record / Restore operation times, and lets you measure ten snapshots of the current document (Measure 10 snapshots). The measurement adds no entries to the history. The change in managed memory depends on garbage collection and does not include texture memory. The CPU time of the Timeline and of document tracking is shown smoothed (without GPU time). In the Unity Profiler use the markers SpriteForge.Timeline and SpriteForge.DocumentTracking.

Autosave and recovery

  • The program periodically saves the session (autosave errors appear in the status: "Autosave failed").
  • The recovery window shows "Document N of M" and a "Recovered / Failed" counter; the Stop after this document button stops the process after the current document.
  • After a crash, Recover unfinished work is offered on start: "An autosaved session is available". The Recover all button (File > Recover all) restores all documents at once and shows the summary "Recovered: N Failed: M".
  • Saving a PNG/JPEG leaves the project unsaved, and the recovery copy is kept until you save the .sf.
  • Project files are written atomically: if something fails the previous version stays.

The memory budget

The default estimated budget is 1 GiB across all open documents. The estimate is conservative: it includes dense tool data, CPU and GPU pixels and working buffers, but it does not measure the process memory as a whole and does not guarantee the absence of allocation failures. The check runs before the change for: creating, importing an image/project/sheet, resizing, duplicating layers and frames, and sparse animation copies. When exceeded "Project memory budget exceeded" is shown and the document stays without partial changes. The current usage is visible as "Estimated memory: X / Y MiB".

Limits: 120 frames per document; the texture size is limited to the maximum allowed.
